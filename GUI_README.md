# Sparx EA Documentation Generator - GUI

A graphical user interface for selective documentation generation from Sparx Enterprise Architect models.

## Features

- **Visual File Selection**: Tree view showing all documents that would be generated by the CLI
- **Selective Generation**: Uncheck documents you don't want to generate
- **Live Preview**: Preview document content before generation
- **Non-Invasive**: Works alongside existing CLI without modifying any generator code
- **Hierarchical View**: Organized by document type (Use Cases, Requirements, Components, Classes, etc.)

## Installation

## Usage

### Starting the GUI

```bash
python sparx_doc_gui.py
```

### Workflow

1. **Open a .qea File**
   - Click "File > Open .qea File..." or click the "Browse..." button
   - Select your Enterprise Architect .qea file
   - The tool will load the model and populate the document tree

2. **Select Documents**
   - All documents are selected by default (☑)
   - Double-click checkboxes to toggle selection
   - Single-click to preview document content
   - Use "Select All" / "Deselect All" for quick selection

3. **Generate Documentation**
   - Click "Generate Selected Documents"
   - Select a parent directory where you want to save documentation
   - Choose output location:
     - **Create New Folder**: Creates a timestamped subfolder (e.g., `docs_20251111_204500`)
       - Edit the suggested name or press Enter to accept
     - **Use Selected Directory**: Saves directly to selected directory
     - **Cancel**: Cancels the generation
   - Wait for generation to complete
   - A success dialog will show when done

## How It Works

The GUI uses a **selective file writer** approach:

1. **Model Extraction**: Uses the same `SparxExtractor` as the CLI to load model data
2. **Tree Building**: Analyzes extracted data to build a complete list of files that would be generated
3. **User Selection**: Presents files in a tree view with checkboxes
4. **Selective Writing**: During generation, intercepts file write operations and only writes selected files

This approach means:
- **No modification to existing generators** - they work exactly as before
- **CLI remains unchanged** - full backward compatibility
- **Same output quality** - uses existing generation logic

## Technical Details

### SelectiveFileWriter

The `SelectiveFileWriter` class patches Python's built-in `open()` function during generation to filter which files get written:

```python
with SelectiveFileWriter(output_dir, selected_files):
    # Any file writes here are filtered
    generator.generate_documentation()
```

- Files in `selected_files` → written normally
- Files not selected → redirected to `/dev/null`
- Files outside output directory → written normally (config, logs, etc.)

### Architecture

```
User selects files in GUI
        ↓
SelectiveFileWriter patches open()
        ↓
CLI generators run normally
        ↓
File writes filtered by SelectiveFileWriter
        ↓
Only selected files written to disk
```

## Examples

### Example 1: Generate Only Use Cases

1. Open your .qea file
2. Click "Deselect All"
3. Expand "use-cases/"
4. Double-click to select the use cases you want
5. Ensure "use-cases/index.md" is selected
6. Ensure root "index.md" is selected
7. Generate

Result: Only selected use case files and necessary indexes are created.

### Example 2: Generate Documentation for Specific Package

1. Open your .qea file
2. Expand "classes/"
3. Expand the package you want (e.g., "domain/")
4. Ensure all classes in that package are checked
5. Uncheck other packages
6. Keep "classes/index.md" and "index.md" checked
7. Generate

Result: Only classes from the selected package are generated.

### Example 3: Generate Reports Only

1. Open your .qea file
2. Click "Deselect All"
3. Check "reports/quality-report.md"
4. Check "reports/dependencies.md"
5. Check "index.md"
6. Generate

Result: Only quality and dependency reports are created.

### Example 4: Organize Documentation by Date

When generating documentation, you can organize outputs by date using the folder creation feature:

1. Open your .qea file
2. Select documents to generate
3. Click "Generate Selected Documents"
4. Select parent directory (e.g., `~/Documents/ProjectDocs/`)
5. In the folder dialog:
   - Accept suggested timestamped name: `docs_20251111_204500`
   - Or edit to custom name: `docs_v2.0_final`
6. Click "Create New Folder"

Result: Documentation saved to organized subfolder:
- `~/Documents/ProjectDocs/docs_20251111_204500/`
- Or `~/Documents/ProjectDocs/docs_v2.0_final/`

This keeps multiple documentation versions organized without overwriting previous ones.

### Example 5: Quick Regeneration to Existing Folder

If you already have a documentation folder and want to regenerate:

1. Open your .qea file
2. Select documents
3. Click "Generate Selected Documents"
4. Navigate to existing parent directory
5. Click "Use Selected Directory"

Result: Documentation regenerated to existing folder, overwriting previous files.

## Troubleshooting

### GUI doesn't start

**Problem**: `ModuleNotFoundError: No module named 'tkinter'`

**Solution**: Install tkinter for your platform (see Installation section above)

### Model doesn't load

**Problem**: Error when opening .qea file

**Solution**:
- Ensure the .qea file is not corrupted
- Check that you have read permissions
- Verify the file is a valid Sparx EA database file

### Generation produces empty folders

**Problem**: Folders created but no files inside

**Solution**:
- Check that you selected the actual files, not just the folders
- Verify the files have checkboxes marked (☑ not ☐)
